## Optimization approaches observed
- Keep decode activations in L1 and width-sharded; keep prefill activations interleaved in DRAM.
- Fused QKV weight (stack WQ/WK/WV) with a single matmul to reduce three linears + concat.
- Fused gate+up MLP weights (stack W_gate/W_up) to allow a single matmul + `swiglu`.
- Use fused SDPA ops (`scaled_dot_product_attention[_decode]`) instead of composing attention from primitives.
- Use DRAM-sharded weights and DRAM-sharded matmul program configs for decode; prefill uses 2D matmul configs on DRAM interleaved tensors.
- Use lower-precision weights (BFP8/BFP4) with LoFi/HiFi2/HiFi4 compute kernel configs when accuracy allows.
- Cache K/V on device: `fill_cache` (prefill) and `paged_update_cache` (decode); shard K/V for long prefill to avoid fill_cache grid limits.
- Use program cache warmup to exclude compile time from performance results.
- Use decode tracing to cut host dispatch overhead for fixed shapes; ensure static addresses and no alloc/dealloc in trace.
- Consider multi-command-queue overlap for host I/O vs op execution.
- Favor L1 sharded activations and avoid redundant data movement; use as many cores as possible.
- Keep norms and small weights in layouts that minimize padding (row-major when supported).
- SDPA program configs matter: chunk sizes (`q_chunk_size`, `k_chunk_size`), exp approximation, and grid sizing drive flash attention/flash decode performance.
- Flash decode can cap per-head parallelism with `max_cores_per_head_batch` to avoid NOC bottlenecks when cores >> heads * batch.
- Decode can use `cur_pos_tensor` (device tensor updated by `ttnn.plus_one`) to keep positions mutable under tracing; lists of positions do not work with trace.
- RoPE options: fused `rotary_embedding_llama` with transformation matrices for decode/prefill, or HF-format `rotary_embedding` with cos/sin caches; pick the format that matches the HF model.
- Prefill reshaping for long seqs (chunking into smaller M) avoids L1 pressure and enables faster matmuls.
- Use `nlp_concat_heads_decode` for decode (avoids transpose) and keep outputs width-sharded for output projection.
- Matmul tuning: prefer `in0_block_w >= 2`, out-subblocks >= 2x1 or 1x2; use 1D matmul for decode when weights stay interleaved, DRAM-sharded for DRAM-bound decode.
- Avoid host-side tilize/untilize; use on-device untilize or on-device sampling (argmax) to reduce host-device traffic where possible.
- Pre-create program configs and shard specs once (init time) and reuse in forward passes to reduce python overhead.
- Argmax supports TILE layout with `use_multicore=False` and `output_tensor`; tile-layout argmax plus a preallocated output buffer can avoid `ttnn.untilize` allocations after trace capture for decode.
- Program cache warmup: run prefill/decode at least once before timing; MeshDevice exposes `enable_program_cache` and related APIs to manage cache policy.
- Trace correctness: preallocate persistent L1 inputs, verify address stability, and avoid bias broadcasting or host prints inside trace; expand biases per batch before capture.
- DRAM-sharded matmul constraints: DRAM grid is 1-row; K/N tile counts must divide across cores; padding is not supported for DRAM-sharded matmuls and per-core N must match shard width.
- Memory/layout basics: sharding applies only on device, host tensors remain row-major; supply shard specs when creating sharded tensors from host.
- Tensor caching: `ttnn.as_tensor(..., cache_file_name=...)` stores weights in `.tensorbin` for faster reloads and reproducible dtype/layout.
- Profiling tools: use TTNN Visualizer + Tracy CSVs to target slow ops and validate sharding/program configs before larger rewrites.

## Optimization checklist from tt-metal sources (2025-01-??)
- Trace decode only: no tensor alloc/dealloc inside trace; preallocate persistent inputs, warm up program cache, and reuse the same device addresses for trace replay.
- Use `trace_region_size` on device open; if trace capture fails, increase the region based on the required size reported.
- Prefer width-sharded L1 activations for decode; choose core grids that evenly divide shard shapes to avoid padding and shard-spec mismatches.
- Use DRAM-sharded weights for decode when DRAM bandwidth dominates; pair with `MatmulMultiCoreReuseMultiCastDRAMShardedProgramConfig` and a core grid that divides K/N exactly.
- Use matmul 2D for prefill (DRAM interleaved); use matmul 1D for decode when weights are interleaved and activations are width-sharded.
- Create program configs up front (in __init__) and reuse; avoid rebuilding per forward pass.
- Fused QKV and fused gate+up (swiglu) are preferred; bias broadcast is not trace-friendly, so expand biases per batch where needed.
- Keep RoPE inputs in the expected format: decode uses per-token cos/sin buffers or `RotarySetup` and `cur_pos_tensor` to stay traceable.
- Use `paged_update_cache` for decode; `fill_cache` / `paged_fill_cache` for prefill; shard KV if fill_cache grid limits are hit.
- Keep SDPA outputs in L1 and avoid unnecessary conversions; tune `q_chunk_size`, `k_chunk_size`, and grid to match batch/core constraints.
- Use row-major layouts for norm weights to avoid padding and improve DRAM access efficiency.
- Avoid host tilize/untilize; if argmax is required, untilize on-device first and read back only small outputs.
- Warmup runs are required to populate program cache before timing.
- Multi-command-queue overlap can hide host IO when inputs are large; use events to coordinate CQ0/CQ1 and keep input buffers persistent.
- Accuracy vs performance knobs: BFP8 + HiFi2 is typical; BFP4 + LoFi for MLP/LM head is a common performance mode, but validate top-1 after changes.

## Optimization approaches (2026-01-12, current session)
- Trace decode only; preallocate persistent inputs, keep L1 addresses stable, warm program cache before capture, and avoid alloc/dealloc or bias broadcast inside trace.
- Warm program cache before timing; exclude first-compile runs from throughput numbers.
- Prefill activations stay DRAM interleaved; decode activations stay L1 width/height sharded; avoid shard padding by selecting core grids that divide shard shapes.
- Prefer DRAM-sharded weights + DRAM-sharded matmul program configs for decode (bandwidth-bound); use matmul 2D for prefill and matmul 1D for decode if weights remain interleaved.
- Fuse QKV weights and fused gate+up (SwiGLU) weights to reduce matmul count; use fused SDPA ops for attention (prefill + decode).
- SDPA decode tuning: q/k chunk sizes, exp_approx_mode, and max_cores_per_head_batch materially affect throughput/accuracy.
- RoPE: use HF-format cos/sin caches with `ttnn.experimental.rotary_embedding` for Llama 3.2 HF format; `rotary_embedding_llama` + RotarySetup is for fused RoPE format.
- KV cache: prefill uses fill_cache/paged_fill_cache; decode uses paged_update_cache with device position tensors; shard KV for long prefill if grid limits are hit.
- Precision/fidelity: BFP8 + HiFi2 baseline; BFP4 + LoFi for FFN/LM head when accuracy allows; raise fidelity if top-1 dips.
- Minimize host-device transfers: avoid host tilize/untilize, use device argmax for greedy decode, and untilize_with_unpadding to trim padding on decode readback.
- Precompute program configs and shard specs at init to reduce per-step Python overhead; consider tensor caching (`cache_file_name`) for faster reloads.
